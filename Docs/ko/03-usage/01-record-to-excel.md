# 3.1 Excel 작업하기

> 이 챕터는 **데이터 작업자** 를 위한 안내입니다. Excel 시트를 어떤 모양으로 채우면 Sdp 가 그대로 받아 가는지 정리합니다. 표준 헤더를 제외하면 시트 구성을 편한 대로 가져가도 된다는 점이 Sdp 의 장점 중 하나입니다. C# 쪽에서 Record 를 작성하는 흐름은 [3.3 첫 Record 정의하기](./03-first-record.md) 에서 다룹니다.

## 시작하기 전에 합의할 것

데이터 작업자가 Sdp 의 도구를 직접 다룰 일은 거의 없습니다. 대신 **레코드 작업자와 아래 항목을 한 번 합의** 해 두면, 그 뒤로는 서로를 기다리지 않고 시트를 채워 나갈 수 있습니다. 합의한 내용은 레코드 작업자가 C# 선언에 그대로 적어 두기 때문에, 바꿀 때는 반드시 알려야 합니다.

|합의 항목|비고|
|-|-|
|**Excel 파일 이름과 시트 이름**|C# 선언의 첫 자리에 적히고 CSV 파일 이름이 된다. 나중에 바꾸면 코드도 바뀌어야 하는 가장 큰 변경|
|**헤더가 시작하는 셀**|예: `B3`. 프로젝트 전체가 같은 위치를 쓰는 편이 단순하다 ([헤더가 시작하는 셀](#헤더가-시작하는-셀))|
|**컬럼 이름 (대소문자 포함)**|C# 쪽 이름과 달라도 된다. 다르면 레코드 작업자가 매핑을 적어 둔다|
|**enum 컬럼의 값 목록**|값 이름을 대소문자까지 그대로 적는다 ([enum 컬럼](#enum-컬럼))|
|**컬렉션 표현 방식과 구분자**|한 셀에 묶는 방식 A 인지, 여러 셀로 펼치는 방식 B 인지 ([컬렉션](#같은-종류의-값이-여러-개--컬렉션))|
|**빈 값 토큰**|비워 둘 수 있는 컬럼이라면 `-` 처럼 빈 값으로 약속할 표기|
|**값의 범위·형식**|가격은 0 이상, 날짜는 `yyyy-MM-dd` 처럼. 레코드 작업자가 선언해 두면 추출 때 자동으로 검사된다|

날짜 컬럼은 한 가지 주의할 점이 있습니다. Excel 에서 날짜 타입으로 입력된 셀은 셀 서식과 무관하게 `yyyy-MM-dd` (시각이 0시인 경우) 또는 `yyyy-MM-dd HH:mm:ss` 문자열로 변환되어 추출됩니다. 따라서 날짜 형식은 이 둘 중 하나로 합의하거나, 다른 형식을 쓰려면 셀을 텍스트로 입력해야 합니다.

</br></br></br>

## 만들 시트 예시

이 챕터를 따라가면서 다루어 볼 시트는 다음 모양입니다.

|       | **A**  | **B**    | **C**       | **D**   | **E**        |
|-------|--------|----------|-------------|---------|--------------|
| **1** | Id     | Name     | Memo        | Price   | Category     |
| **2** | 1      | Potion   | 회복 아이템   | 100     | Consumable   |
| **3** | 2      | Sword    | 기본 검      | 5000    | Weapon       |
| **4** | 3      | Shield   | 기본 방패    | 4000    | Armor        |

- **1행이 헤더**, **2행부터 데이터** 입니다.
- `Memo` 는 데이터 작업자끼리만 보는 메모 컬럼입니다. 레코드 작업자에게 알리지 않은 컬럼은 그대로 무시되므로, 시트 안에서 자유롭게 둘 수 있습니다 (자세히는 [참고 컬럼은 그대로 둬도 된다](#참고-컬럼은-그대로-둬도-된다)).
- `Category` 처럼 정해진 값 목록 중 하나를 골라 적는 **enum 컬럼** 은 값 이름을 그대로 적습니다.

컬럼 이름의 대소문자 표기는 레코드 작업자와 한 번 합의되면 그대로 유지합니다.

</br></br></br>

## 헤더가 시작하는 셀

시트의 첫 헤더가 꼭 `A1` 일 필요는 없습니다. **어느 셀에서 시작해도 무관** 합니다. 위쪽이나 왼쪽에 시트 제목이나 이 시트가 어떤 데이터를 담는지 적어 두고 싶으면 그만큼 떨어뜨려 헤더를 시작해도 됩니다.

|       | **A** | **B**             | **C**    | **D**     | **E**   | **F**        |
|-------|-------|-------------------|----------|-----------|---------|--------------|
| **1** |       | 아이템 테이블        |          |           |         |              |
| **2** |       | 상점에 노출되는 아이템의 기본 정보 | |        |         |              |
| **3** |       | Id                | Name     | Memo      | Price   | Category     |
| **4** |       | 1                 | Potion   | 회복 아이템 | 100     | Consumable   |

이 경우 시작 셀이 `B3` 가 됩니다. `A` 열과 `1`, `2` 행은 추출기가 읽지 않는 자유 영역이라, 시트 제목이나 이 테이블이 어떤 데이터를 담는지 같은 설명을 적어 두기 좋습니다. 시작 셀 위치는 레코드 작업자와 한 번 합의해 두면 되며, 한 프로젝트 안의 모든 시트가 같은 시작 위치를 쓰는 편이 단순합니다.

</br></br></br>

## 참고 컬럼은 그대로 둬도 된다

비고나 메모처럼 시트 안에서만 보고 싶은 컬럼이 자주 필요합니다. **레코드 작업자에게 알리지 않은 컬럼은 추출 시 그대로 무시됩니다.** 위 예시의 `Memo` 컬럼이 그 경우입니다 — 데이터 작업자끼리 공유할 메모를 시트에 그대로 남길 수 있다는 의미입니다.

반대로 합의된 컬럼이 시트에 **없으면 추출이 실패합니다.**

시트의 컬럼 순서는 Record 와 달라도 됩니다. 추출기는 헤더 이름으로 컬럼을 찾으므로, 합의한 컬럼의 이름만 맞으면 시트 안에서 순서를 자유롭게 바꿀 수 있습니다.

`Tags[0]`, `Tags[1]` 처럼 번호가 붙은 컬럼 묶음은 Record 가 길이를 고정하지 않은 경우(표준 헤더에 `[0]` 만 있는 경우) 필요한 만큼 `[1]`, `[2]`, … 를 이어서 추가할 수 있습니다. 번호는 0 부터 빠짐없이 이어져야 합니다. `[1]` 부터 시작하거나 중간 번호가 비면 추출이 실패합니다.

합의된 컬럼이 모두 비어 있는 행은 통째로 건너뜁니다. 데이터 사이에 빈 행을 두어도 되고, `Memo` 처럼 합의되지 않은 컬럼만 채운 행은 결과에 포함되지 않습니다.

</br></br></br>

## enum 컬럼

`Category` 처럼 미리 정해진 값 목록 중에서 하나를 골라 적는 컬럼을 **enum 컬럼** 이라고 부릅니다. 셀에는 **값 이름** 을 그대로 적습니다.

|       | **A**  | **B**    | **C**        |
|-------|--------|----------|--------------|
| **1** | Id     | Name     | Category     |
| **2** | 1      | Potion   | Consumable   |
| **3** | 2      | Sword    | Weapon       |

표기는 **대소문자까지 정확히** 일치해야 합니다. `consumable`, `CONSUMABLE`, 목록에 없는 이름 (`Magic` 등) 은 모두 추출 실패가 됩니다. 값은 멤버 이름만 허용되며, `1` 같은 정수 값도 추출기가 거부합니다. 단, `[Key]` 가 붙은 enum 컬럼은 추출기가 값 목록 검사를 건너뜁니다. 로드 단계에서 생성된 변환 코드는 멤버 이름과 정수 값 문자열 (`1`) 을 모두 받습니다 (대소문자 구분).

값 목록은 레코드 작업자와 합의해서 받아 두는 정보입니다.

</br></br></br>

## 문자열 셀의 쉼표, 줄바꿈, 큰따옴표

문자열 셀에는 쉼표, 줄바꿈 (`Alt+Enter`), 큰따옴표를 그대로 넣어도 됩니다. 추가 처리 없이 시트에 보이는 그대로 보존됩니다.

|       | **A**  | **B**    | **C**                              |
|-------|--------|----------|------------------------------------|
| **1** | Id     | Name     | Description                        |
| **2** | 1      | Potion   | HP, MP를 회복                       |
| **3** | 2      | Letter   | "안녕"이라고<br>적혀 있다           |

3번 행 `Description` 셀은 Excel 셀 안에서 `Alt+Enter` 로 줄바꿈한 값입니다. 이 줄바꿈은 보이는 그대로 보존됩니다.

</br></br></br>

## 같은 종류의 값이 여러 개 — 컬렉션

한 행에 같은 종류의 값을 여러 개 담아야 할 때가 있습니다. 예를 들어 한 아이템이 보유한 태그 목록처럼 말입니다. 두 가지 표현 방식 중 데이터의 성격에 맞는 쪽을 고릅니다. 어느 방식을 쓸지는 레코드 작업자와 한 번 합의해 두면 됩니다.

### 방식 A — 한 셀에 구분자로 묶기

태그가 그저 라벨이고 개별 값 검토가 필요 없다면, **한 셀에 구분자로 묶어 두는** 방식이 가벼워서 좋습니다.

|       | **A**  | **B**    | **C**               |
|-------|--------|----------|---------------------|
| **1** | Id     | Name     | Tags                |
| **2** | 1      | Potion   | heal,consumable     |
| **3** | 2      | Sword    | melee,iron          |
| **4** | 3      | Shield   | defense,iron        |

</br>

구분자는 쉼표 한 글자에 한정되지 않습니다. `|`, `;`, ` / ` 같은 한 글자뿐 아니라 `, `, ` - ` 처럼 여러 글자로 된 문자열도 구분자로 쓸 수 있습니다. 시트 안의 값과 겹치지만 않으면 되고, 어떤 구분자를 쓸지는 레코드 작업자와 한 번 합의해 두면 됩니다. 예를 들어 태그 안에 쉼표가 들어가는 경우라면 다음처럼 ` | ` (양옆에 공백 한 칸) 를 구분자로 약속해 한눈에 더 잘 보이게 둘 수 있습니다.

|       | **A**  | **B**    | **C**                       |
|-------|--------|----------|-----------------------------|
| **1** | Id     | Name     | Tags                        |
| **2** | 1      | Potion   | heal \| consumable, small   |
| **3** | 2      | Sword    | melee \| iron, starter      |

</br>

- 한 줄이 짧고 한눈에 묶여 보입니다.
- **나중에 항목 개수가 늘어나도 합의 없이 그대로 적용됩니다** — 셀에 항목만 추가하면 됩니다.
- 단, Excel 자체에서 개별 항목 단위로 정렬, 필터링은 어렵습니다.
- 구분자 앞뒤의 공백은 제거됩니다. `heal, consumable` 로 적어도 `heal`, `consumable` 로 읽힙니다.
- 비어 있거나 공백뿐인 항목 (`heal,,iron` 등) 은 추출 실패가 됩니다. 셀을 통째로 비우면 항목 0개 (빈 컬렉션) 로 처리됩니다. 항목이 하나 이상 있어야 하는 컬럼이면 레코드 작업자가 `[CountRange]` 의 하한으로 강제합니다.

</br></br>

### 방식 B — 여러 셀로 펼치기

태그 하나하나를 검토하거나 셀 단위로 정렬, 필터링하고 싶다면 **여러 셀로 펼치는** 방식이 유리합니다.

|       | **A**  | **B**    | **C**     | **D**        | **E**     |
|-------|--------|----------|-----------|--------------|-----------|
| **1** | Id     | Name     | Tags[0]   | Tags[1]      | Tags[2]   |
| **2** | 1      | Potion   | heal      | consumable   | small     |
| **3** | 2      | Sword    | melee     | iron         | starter   |
| **4** | 3      | Shield   | defense   | iron         | starter   |

</br>

- Excel 의 필터, 정렬 기능이 각 항목을 독립적으로 다룰 수 있습니다.
- 컬럼 개수가 정해져 있으므로 늘리거나 줄이려면 레코드 작업자와 합의가 필요합니다.
- 칸을 비워 두고 싶을 때는 어떤 토큰 (`"-"`, `빈 칸` 등) 을 빈 값으로 약속할지 한 번 합의해 두면 됩니다.

</br></br>

두 방식 사이의 선택은 다음과 같이 생각해 볼 수 있습니다.

- 컬럼 수가 자주 늘어나거나 줄어들 가능성이 있다면 **방식 A** 가 관리 편의성에서 유리합니다.
- 컬럼 수가 고정되고 셀 단위 정렬/필터를 활용하고 싶다면 **방식 B** 가 유리합니다.

</br></br></br>

## 객체 여러 개 — 객체의 배열

태그처럼 단순한 값이 아니라, **여러 필드를 가진 묶음** 이 한 행에 여러 개 들어가는 경우가 있습니다. 예를 들어 학생 한 명이 여러 과목의 성적을 가지는 시트입니다. 작업 중에는 알아보기 쉬운 임시 헤더로 먼저 적어 두는 편이 자연스럽습니다.

이런 데이터를 `수학과목`, `수학점수`, `영어과목`, `영어점수` … 처럼 필드를 옆으로 죽 나열하는 대신 **객체의 컬렉션** 으로 묶어 두면, C# 코드에서 과목 수만큼 `foreach` 반복문 한 번으로 처리할 수 있습니다. 필드를 나열하는 방식은 항목이 늘 때마다 코드도 그만큼 늘려 가며 일일이 다뤄야 하지만, 컬렉션으로 두면 같은 반복문이 항목 수와 무관하게 그대로 동작합니다. 한 행에 같은 종류의 묶음이 여러 개라면 컬렉션으로 작성하는 편이 거의 항상 유리합니다.

|       | **A** | **B**   | **C**        | **D**     | **E**          | **F**       | **G**         | **H**      |
|-------|-------|---------|--------------|-----------|----------------|-------------|---------------|------------|
| **1** | Id    | Name    | 수학과목     | 수학점수  | 영어과목       | 영어점수    | 과학과목      | 과학점수   |
| **2** | 1     | Alice   | Math         | 90        | English        | 85          | Science       | 88         |
| **3** | 2     | Bob     | Math         | 70        | English        | 95          | Science       | 75         |
| **4** | 3     | Carol   | Math         | 80        | English        | 80          | Science       | 90         |

그러나 자동 추출이 동작하려면 헤더가 정해진 표준 형태여야 합니다. 위 시트의 표준 헤더는 다음과 같이 길어집니다.

|       | **A** | **B**   | **C**                 | **D**               | **E**                 | **F**               | **G**                 | **H**               |
|-------|-------|---------|-----------------------|---------------------|-----------------------|---------------------|-----------------------|---------------------|
| **1** | Id    | Name    | Subjects[0].Subject   | Subjects[0].Score   | Subjects[1].Subject   | Subjects[1].Score   | Subjects[2].Subject   | Subjects[2].Score   |

이 표준 헤더를 손으로 맞추는 일은 만만치 않습니다. 데이터 합의가 끝나면 이 부분은 **표준 헤더 생성기** 가 자동으로 채워 줍니다. 다음 챕터에서 이어 가겠습니다.

</br></br></br>

## 푸시 전에 직접 확인하기

시트를 커밋·푸시하면 보통 CI 가 `ExcelColumnExtractor` 를 돌려 헤더 누락, 값과 타입 불일치, enum 이름 오타, 범위 위반 같은 문제를 잡아 줍니다. 그런데 CI 결과를 기다리지 않고 **자기 자리에서 바로 확인** 할 수도 있습니다. 추출기는 .NET 설치 없이 실행되는 단일 실행 파일이고, Record `.cs` 폴더와 Excel 폴더만 있으면 돌아갑니다.

```bash
ExcelColumnExtractor.exe ^
  --record-path ./Records ^
  --excel-path ./Excels ^
  --output-path ./csv-check ^
  --start-cell B3
```

- Record `.cs` 폴더는 레코드 작업자가 공유해 준 위치 (보통 같은 저장소 안) 를 그대로 가리킵니다.
- **Excel 파일이 열려 있어도 됩니다.** 추출기는 잠긴 파일을 사본으로 떠서 읽습니다. 작업 중에 바로 돌려 볼 수 있다는 뜻입니다.
- 실패하면 어느 시트의 어느 컬럼, 어느 값이 문제인지 메시지로 알려 줍니다. 셀을 고치고 다시 돌리는 반복이 자연스럽습니다.
- 실행 중에 Excel 이나 `.cs` 파일이 바뀌면 경고를 남깁니다. 단, 수정 시각이 실행 시작 시점보다 과거로 바뀐 파일이 있으면 실패합니다. 저장 직후에 돌리는 편이 안전합니다.

```mermaid
flowchart LR
    Edit["시트 수정"] --> Run["ExcelColumnExtractor 실행"]
    Run -->|성공| Push["커밋 · 푸시"]
    Run -->|실패: 시트·컬럼·값 메시지| Edit
```

한 가지, **다른 시트를 가리키는 ID (외래 키) 가 실제로 존재하는지는 추출기가 검사하지 않습니다.** 그 검사는 런타임에서 데이터를 로드할 때 일어나므로 ([3.6](./06-foreign-keys.md)), 레코드 작업자 쪽에서 로드 테스트를 CI 에 두는 것이 보통입니다.
